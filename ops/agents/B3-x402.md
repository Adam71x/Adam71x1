# B3: x402 pay-per-call API (USDC on Base)

Window: 14:59 to 15:06 UTC, 2026-09-24 (about 7 minutes).
payTo: `0xA973f9F3D582189D5941e09cB4d198ca1e8E99cA` (public address only; no private key used anywhere).
Money verified: **$0**. Nothing is public, so no buyer could have paid.

## Result

- **Built and tested locally:** `products/x402-api/` runs an x402 v2 paid endpoint, `POST /grade`, priced at $0.02 USDC on Base mainnet (`eip155:8453`). It uses the official `@x402/express`, `@x402/core`, `@x402/evm` and `@x402/extensions` packages (v2.27.0). When a request arrives without payment, it returns `402 Payment Required` with correct payment requirements.
- **Settlement needs no account.** The PayAI facilitator settles exact payments on Base mainnet with no API key.
- **Not live.** This sandbox can't host it publicly. Its egress only passes TLS on port 443, through a TLS-intercepting proxy. Every account-free tunnel needs something else: raw TCP, SSH, or TLS on another port. Details are under "Hosting" below.
- **Owner can publish in one step**, from any normal machine (see below).

## Evidence: getting paid with no account

| Facilitator | Base mainnet? | Account/key? | Evidence |
|---|---|---|---|
| x402.org (reference) | **No.** EVM support is testnet only (`eip155:84532`, `base-sepolia`) | none | `curl https://x402.org/facilitator/supported`: the only EVM entries are 84532 and base-sepolia |
| Coinbase CDP | yes | **Yes, needs CDP API keys** | `curl https://api.cdp.coinbase.com/platform/v2/x402/supported` returns `401 Unauthorized` |
| **PayAI** (`facilitator.payai.network`) | **yes** (`x402Version 2, exact, eip155:8453` and v1 `base`) | **No, for exact payments** | docs.payai.network/x402/facilitators/pricing.md says: "1,000 free credits per receiving wallet (lifetime) — roughly 650 Solana or 430 Base settlements" and "No API key required for ordinary exact payments". authentication.md says: "Ordinary exact payments can use the free tier without an API key." |
| mogami (`facilitator.mogami.tech`) | yes (v1 `base`) | not checked | `/supported` returns `base-sepolia` and `base` |
| x402.rs | no `eip155:8453` in `/supported` | | |

How the money moves: the buyer signs an EIP-3009 `transferWithAuthorization`. The facilitator submits it and pays the gas, and the USDC goes straight to payTo. The seller never holds a key. PayAI's free allowance (about 430 Base settlements per wallet) is enough to test demand. After that it charges cost-plus credits, and those need a merchant account. An agent can also buy a key over x402 with no account (docs: agent-api-keys.md).

**Discovery (Bazaar).** The route declares the `bazaar` discovery extension: input schema, example and output example. PayAI runs a public catalog: `GET https://facilitator.payai.network/discovery/resources` returns 200 and lists Base resources that carry bazaar metadata. **Inference, not verified:** facilitators appear to add a resource to the catalog when they process a payment for it. That means the listing would appear after the first paid call. There is no separate account-free "submit" step, and any listing needs a public URL first.

## Verified 402 response (local)

`POST http://localhost:4021/grade` with no payment returned `HTTP/1.1 402 Payment Required`. The base64 `PAYMENT-REQUIRED` header decodes to the following (saved in `products/x402-api/402-accepts.json`):

```json
{"scheme":"exact","network":"eip155:8453","amount":"20000",
 "asset":"0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
 "payTo":"0xA973f9F3D582189D5941e09cB4d198ca1e8E99cA",
 "maxTimeoutSeconds":300,"extra":{"name":"USD Coin","version":"2"}}
```

- `amount` 20000 = $0.02 (USDC has 6 decimals).
- `asset` is native USDC on Base.
- The header also carries the `bazaar` extension with the input and output schemas.

## Hosting: what I tried and what blocked it

| Try | Result | Evidence |
|---|---|---|
| localhost.run / serveo (SSH `-R`) | No `ssh` binary. Raw TCP out is blocked. | `ssh: No such file`. `/dev/tcp/bore.pub/2200` timed out. |
| localtunnel (`localtunnel.me`, no account) | The API works: `GET /?new` returns `{"url":"https://readme-grader-x402.loca.lt","port":7607}`. The data socket to port 7607 never connects. The local proxy answers CONNECT with 200, but the upstream relay closes it. | `/api/tunnels/readme-grader-x402/status` returns `{"connected_sockets":0}`. The proxy log shows `ws_closed_mid_exchange ... localtunnel.me:7607 ... 0 B sent`. The public URL returns 502. |
| tunnelmole (no account) | Needs `wss://service.tunnelmole.com:8083`. The TLS handshake is reset. | curl: `SSL_connect: Connection reset by peer`. The proxy log shows the same failure for port 8083. |
| pinggy (SSH over port 443) | The SSH banner never comes back. The relay only carries TLS. | Proxy log: `a.pinggy.io:443 ... 13 B sent` then closed. |
| cloudflared quick tunnel | The edge port 7844 is unreachable. Cloudflare's edge TLS would also fail behind the intercepting proxy. | `https://region1.v2.argotunnel.com:7844` returns 000. |
| Free serverless hosts (Deno Deploy, Val Town, Vercel, Render, Cloudflare Workers) | All need an account. Not attempted. | |

Conclusion: the block is this sandbox's network (TLS on port 443 only), not the method. On a normal machine, two routes need no account:

- localhost.run docs: "no account setup is needed for free domains."
- Cloudflare docs, Quick Tunnels: "experiment with Cloudflare Tunnel without adding a site... generates a random subdomain on trycloudflare.com." Cloudflare frames quick tunnels as testing and experimentation, so treat them as a trial, not production hosting.

## To go live (owner, about 2 minutes, no signup)

```bash
cd products/x402-api && npm ci && npm start          # :4021
ssh -R 80:localhost:4021 nokey@localhost.run          # prints https://<random>.lhr.life
#   or: cloudflared tunnel --url http://localhost:4021  (https://<random>.trycloudflare.com)
```

The tunnel URL changes on every restart. Discovery listings will then point to a dead URL, so keep the process running. After that, one paid call through any x402 client puts it in PayAI's discovery catalog (inferred, see above). The buyer pays, not the owner.
